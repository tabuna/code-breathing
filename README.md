# 🫁 Code Breathing Analyzer

На многих сайтах можно встретить надпись:

> «Чтение этой статьи займёт всего 5 минут.»

Это значение вычисляется исходя из количества слов и средней скорости чтения — и, как правило, оказывается достаточно точным.

**А что, если применить похожий подход к программному коду?**

**Code Breathing Analyzer** — это инструмент, который оценивает *дыхание кода*,
измеряя **плотность строк** и выявляя **слишком длинные блоки без визуальных пауз** (пустых строк).

Попробуйте посмотреть:
```php
XXXXXXXXXXXXXXXXXXX XX XX XX XXXXXXXX XXX XX XXXXX XXX
    XXXXX XX XXXX

    XXXXXXX XXXXXXXX XXXXXXX XXXXX
        XXXXXX XXXXXXXX XXXXX XX XXXXXXX XXXXX XXXXX XXX
            XX XXXXX XXXXXXXX XXX
                XXXXXXXXXXXXXXXXXXXXXXXX 
                XXXXXXX XX XXXXXXXXXX XXXXXXXXX 
                    X XXXXX XXXXX 
                    X XXXXX XXXX
            XX XXXX
                XXXXXXX XX XXXXX
            XX
        XX
    XX

    XXXXX XXXXXXX
XX
```

Нам намного приятнее читать текст, который бы 

```php
XXXXXXXX XXXXX XXX

    XX XXXXX XXXXXXXX XXX
        XXXXX XX XXXX
    XX

    XXXXX XXXXXXX
XX
```

Во втором примере, сильно меньше текста....


Иногда код выглядит компактным, но читается тяжело из-за **длинных имён переменных и функций**, перегружающих зрительное восприятие.

Сравните два эквивалентных фрагмента:

```php
// Вариант A
function add($a, $b) {
    return $a + $b;
}
```

```php
// Вариант B
function addTwoNumbersWithMeaningfulNames($firstOperandValue, $secondOperandValue) {
    return $firstOperandValue + $secondOperandValue;
}
```

Обе функции делают одно и то же,
но **вторая** воспринимается заметно тяжелее -
глазу сложнее «схватывать» длинные идентификаторы, внимание рассеивается,
а общее «дыхание» кода сокращается.


Для повышения читаемости кода стоит применять:

- Пустые строки между логическими блоками.
- Разделение длинных функций на подфункции.
- Минимизацию плотных блоков > 5 строк без пауз.


> [!WARNING]  
> Следует учитывать синтаксис и стиль: языки типа `C` требуют обязательных скобок и запятых,
> которые создают визуальные паузы, а однобуквенные имена переменных и функций 
> могут искусственно снижать плотность, не отражая реальной когнитивной нагрузки.


### Cognitive Density Index (CDI)

Чтобы количественно оценить это явление, используется **индекс когнитивной плотности**:

[
CDI = \frac{\Sigma(\text{длина всех токенов})}{\text{количество непустых строк}}
]

Он показывает, насколько “текстово плотен” код.
Чем выше CDI — тем сложнее код воспринимать беглым взглядом.

### Line Density Index (LDI) — Средняя длина непрерывного блока кода без пустых строк.
Пример: если функция содержит 50 строк, но каждые 5 строк разделены пустыми — LDI = 5.


### Breathing Score (BS) — Интегральный показатель «дыхания» файла.
Рассчитывается как обратная величина LDI, скорректированная на количество функций и отступов:
   [
   BS = \frac{1}{1 + \text{LDI}/10} + \frac{\text{avg_indent}}{10}
   ]
   Чем ближе к 1 — тем легче читать код.


### Block Smoothness (BSM) - Оценка равномерности пустых строк: насколько «ритмично» они распределены.
Используется дисперсия расстояний между пустыми строками.
   > Малое отклонение → код ритмичен и дышит.

### Long Block Warning
Предупреждения о блоках > `N` строк без визуальной паузы (например, 5 строк).


### Cognitive Density Index (CDI)

 Формула:
[
CDI = \frac{\text{Σ(длина всех токенов)}}{\text{количество непустых строк}}
]

> Чем выше значение — тем плотнее код.
> При чтении "длинных слов" мозг делает меньше пауз, но тратит больше усилий на распознавание.

Дополнительный коэффициент:

[
C_{\text{name}} = \frac{\text{средняя длина идентификатора}}{10}
]

Если `C_name > 1.2`, код считается **перегруженным по именам**
(например: `$superVeryComplicatedInternalProcessHandler`).
